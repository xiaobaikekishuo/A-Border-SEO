# A-Border SEO 受管桌面版

管理服务保存产品、管理员、注册用户、设备、维护策略、发行配置和审计记录。Windows 客户端主动通过 HTTPS 注册、登录、续签授权并上报执行结果。本地 PostgreSQL、SEO 数据和 Google、ChatGPT、Manus 凭据留在客户端。1.4.0 受管工作台使用注册账号登录，进入工作台不再依赖 Google OAuth。

## 部署与打包

1. 在自己的服务器按 [管理服务部署说明](../control-plane/README.md) 初始化管理员、生成 Ed25519 签名密钥并启动 HTTPS。管理员从该域名的 `/admin/` 进入网页后台。
2. 准备公开信任配置。将 `serverUrl` 和 `issuer` 均设为管理服务 HTTPS origin（无子路径），`productId` 设为 `a-border-seo`，`keys` 填入以服务端签名 `kid` 为键的 PEM 公钥。私钥由服务端保存。
3. 正式发行时，在 GitHub Actions 仓库变量 `ABORDER_MANAGEMENT_CONFIG_JSON` 中放入公开信任配置。打包工作流将其写入安装包，并绑定同一版后台镜像的 GHCR 摘要。维护者也可以在打包前用 `node scripts/stage-management-config.mjs <公开配置.json>` 进行本地验证。 [发行说明](RELEASE.md)
4. 安装受管版本后，用户在客户端注册用户名和密码。新账号默认为待审核，不能获得业务授权。管理员在账号授权页选择“审核注册”，填写授权期限、设备上限和功能，勾选“批准注册并启用账号”后保存。
5. 用户登录后绑定设备，客户端自动准备本地服务并直接进入工作台。服务配置、接管旧安装、备份和诊断位于设置页。已有安装先升级到相同版本的后台镜像，再核对两个 worker 回执。

旧版激活码保留作兼容和设备重绑用途。已激活但没有注册用户的安装可凭原设备凭据关联新注册账号，关联后需要管理员批准；新版不会把激活码视为用户登录。解除绑定会使旧设备凭据进入吊销状态。

工作台会话来自已验证的签名授权与本机私有登录凭据，按管理服务、产品和授权账号映射到本地用户。不会按未验证的邮箱合并数据。旧 Google 用户、站点和授权仍保存在原数据库，不能自动转交给新账号。后台调度、普通任务、内容任务和读取密钥同样核对当前账号归属。退出登录会移除本地签名授权投影、设备登录凭据和浏览器会话，并使旧工作台 cookie 失效。

## 策略与执行结果

- 产品、账号、设备和设备组策略可以叠加。解除维护不会解除账号停用、设备吊销或版本限制。功能开关涵盖一般后台任务、Codex 内容任务、Manus 和 GEO。
- 维护时允许按原权限查看已有数据。停用或授权到期时限制业务入口，控制台仍保留备份、诊断、更新和重新授权。策略暂停新任务，已领取的任务可按原有租约规则完成或安全写回。已经提交给第三方的任务保留其任务 ID。
- 管理后台以设备实际续签和回执记录在线状态、桌面和后台版本。收到策略表示客户端已保存当前授权；已生效还要求本地应用和普通 worker 确认相同策略，并且受影响的在途工作已收尾。应用未运行或无法验证时保持待确认状态。
- 建议约每分钟刷新，加入抖动和失败退避。默认授权 15 分钟，服务端可以配置期限。管理服务暂时故障时使用尚未到期的已验证授权，重启不会延长到期时间。收到签名停用策略后会立即取代之前的授权。关闭控制台窗口到托盘时仍会续签。完全退出或关机后，后台在现有授权到期时进入受限状态。
- 密钥轮换先通过签名安装包下发新旧两个公钥，然后切换服务端签名 `kid`，最后在后续发行包移除旧公钥。客户端持久记录最近接受的序列号、策略版本和观察时钟，拒绝重放、错误绑定和明显时钟回退。

## 版本下发

先为指定设备组分配测试发行，再扩大稳定渠道比例。设备分批分组以安装标识为依据保持稳定。推荐更新可稍后安装。最低桌面或后台版本生效后限制业务，更新和诊断入口仍可用。

管理服务验证官方发行文件与可拉取的后台镜像，再允许激活版本策略。Windows 客户端只检查分配给本设备的版本，并按现有安装包签名和摘要规则下载。重启安装后继续对后台执行备份、迁移和健康检查。只有桌面与后台版本均与目标相符，且本地健康检查成功后，才上报更新完成。测试组出现更新失败会阻止扩大投放，应先暂停扩大，再修复并发布新版本。数据库恢复流程见 [接管、备份与恢复](DATA-MIGRATION.md)。

## 隔离验收

在仓库根目录运行：

```powershell
node --test desktop/test/*.test.mjs
node --test control-plane/test/*.test.mjs
```

使用两个独立 Windows 测试环境和数据库注册设备。分别测试单设备停用、账号停用、全局维护及恢复，并尝试从系统浏览器直接访问本地业务接口。检查在途任务的回执从收到变为收尾，最后显示已生效。断开测试管理服务，观察剩余授权和到期后的限制。恢复连接时应显示服务端最新策略。最后用两个真实签名测试发行验证分批推送和两层升级。

管理能力只覆盖已接入协议、按协议运行的安装。断网或关机设备显示最后确认状态，在缓存授权到期前可能继续使用。拥有本地管理员权限并能修改程序、文件或系统时间的用户可以改变本地运行行为。
